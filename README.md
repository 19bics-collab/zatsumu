# zatsumu 🪑

テレワーク勤怠・稼働可視化ツールの MVP（F-Chair+ 風）。

着席／退席の打刻、ランダム間隔のスクリーンショット送信、管理者向けの
リアルタイム稼働状況ダッシュボードを提供します。

## 構成

```
[client/agent.py]  --HTTP-->  [server (FastAPI)]  -->  [SQLite + 画像ファイル]
 打刻 / スクショ撮影・送信       認証 / 集計 / 配信            data/
                                     |
                              [/admin ダッシュボード]
```

| ディレクトリ | 役割 |
|---|---|
| `server/` | FastAPI サーバ（打刻 API・スクショ受信・管理画面・月次レポート・保存期間管理） |
| `client/` | 常駐エージェント（`agent.py` CLI 版 / `tray.py` トレイ常駐版 / `widget.py` 常時表示バー版） |
| `manage.py` | ユーザー作成・スクショ削除・確認済み端末の管理 CLI |
| `tests/` | API テスト |
| `deploy/` + `Dockerfile` 等 | 本番デプロイ用（**[DEPLOY.md](DEPLOY.md)** 参照） |

## 5分でデモサイトを立ち上げる

`ZATSUMU_DEMO=1` を付けて起動すると、固定トークンのデモユーザーと架空の
勤務データ・キャプチャが自動投入されます（DB が空のときのみ）。

| 役割 | 名前 | トークン |
|---|---|---|
| 管理者 | 管理者 | `demo-admin` |
| メンバー | 田中 / 鈴木 / 佐藤 | `demo-tanaka` / `demo-suzuki` / `demo-sato` |

**クラウドで（無料・PC へのインストール不要）** — [Render](https://render.com) の無料プランを使用:

1. GitHub アカウントで Render にサインアップ
2. New + → Web Service → このリポジトリを接続
3. Runtime: **Docker** / Instance Type: **Free** を選択
4. Environment Variables に `ZATSUMU_DEMO` = `1` を追加して Create Web Service
5. 発行された `https://xxx.onrender.com/admin` を開き、`demo-admin` でログイン

無料プランはアクセスが無いとスリープし、データは再起動のたびにリセット
されます（デモ用途には十分）。**固定トークンのため本番では絶対に
`ZATSUMU_DEMO=1` を使わないでください。**

**ローカルで（一発起動）** — Python 3.10+ が入っていれば1コマンド:

```bash
python demo.py     # Windows は demo.bat をダブルクリックでも可
```

ライブラリの自動インストール → デモデータ投入 → サーバ起動 → ブラウザで
管理画面を自動オープン、までやってくれます。終了は Ctrl+C。

## 本番公開

社内サーバやクラウドへのデプロイ手順は **[DEPLOY.md](DEPLOY.md)** にまとめてあります
（Docker / systemd / Windows / Render の各パターンと、HTTPS・DNS の設定方法）。

## ローカルでのセットアップ（開発・お試し用）

```bash
pip install -r requirements.txt

# ユーザー作成（表示されるトークンを控える）
python manage.py add-user 田中
python manage.py add-user 管理者 --admin

# サーバ起動
uvicorn server.app:app --host 0.0.0.0 --port 8000
```

## 使い方

**メンバー側 — Webで打刻・実績確認（インストール不要・スマホ対応）**:
`http://<server>:8000/me` を開き、自分のトークンでログイン。大きなボタンを
タップして着席/退席を切り替えます。**作業区分**（例：事務作業／現場）の
ボタンで、在席中に区分をワンタップで切り替えられます（現場に出た／事務に
戻った、を記録）。同じページで**自分の勤務実績**（月別の日別タイムライン、
区分ごとに色分け・合計時間）と**自分のキャプチャ**を確認できます
（キャプチャの閲覧は本人と管理者のみ、削除は管理者のみ）。
※ Web 打刻では PC 画面のキャプチャは記録されません（キャプチャが必要な場合は
下記の PC 用クライアントを使用）。

**メンバー側 — PC 用クライアント**（スクショ送信あり。Ctrl+C で退席）:

```bash
# CLI 版
python -m client.agent --server http://<server>:8000 --token <自分のトークン>

# システムトレイ常駐版（トレイアイコンから着席/退席をワンクリック）
python -m client.tray --server http://<server>:8000 --token <自分のトークン>

# 常時表示バー版（画面隅に小さなバー。着席中=青+経過時間 / 退席中=赤。クリックで切替）
python -m client.widget --server http://<server>:8000 --token <自分のトークン>
```

スクショは既定で 1 時間に約 6 回（5〜15 分のランダム間隔）撮影されます。
オプション: `--min-interval/--max-interval`（間隔・秒）、
`--blur N`（プライバシー配慮のぼかし）。

`--server`/`--token` は省略可能で、環境変数（`ZATSUMU_SERVER`/`ZATSUMU_TOKEN`）や
同じフォルダの `zatsumu_config.json` からも読み込みます。社員に配布する場合は、
**Python 不要の単体 `.exe`**（`build_client.ps1` でビルド、初回だけトークン入力）が
便利です。手順は **[DEPLOY.md](DEPLOY.md)** の「メンバー側の設定」を参照してください。

**管理者側**: ブラウザで `http://<server>:8000/admin` を開き、管理者トークンで
ログインします。

- **稼働状況**: 着席状況・本日の在席時間・本日のミニタイムライン・最新キャプチャを
  30 秒ごとに自動更新。退席し忘れたメンバーは**強制退席**ボタンで退席にできます。
  名前をクリックすると**個人ページ**（日別タイムライン）が開きます
- **個人ページ**: 青いバー（在席）をクリックすると**打刻の修正・削除**、
  「＋打刻を追加」で手動追加ができます（操作はすべて修正履歴に記録）。
  キャプチャの点はクリックで拡大表示、**← → キーまたはボタンで前後に移動**できます
- **メンバー管理**: 画面からメンバー追加（トークンは作成時に一度だけ表示）、
  トークン再発行、無効化/有効化、管理者権限の付与/解除
- **月次レポート**: 全員の勤務日数・合計時間の一覧と、
  月次集計 / **日別集計** / 在席データ / **修正履歴**の CSV ダウンロード
- **作業区分**: 「事務作業／現場」などの区分を設定でき、メンバーが在席中に
  切り替え可能。個人ページのタイムラインは区分ごとに色分けされ、区分別の
  合計時間も集計されます（在席データ CSV にも区分列が出力されます）
- **チーム（部署）**: メンバーをチームに分け、稼働状況をチームで絞り込み表示。
  メンバー管理タブでチームの作成・改名・削除と所属の割り当てができます
- **休暇・欠勤の申請／承認**: メンバーは `/me` から休暇（有給・半休・欠勤など）を
  申請でき、管理者は「申請」タブで承認/却下します（承認待ち件数をバッジ表示、
  通知が有効なら申請を Slack/メールへ周知）。承認状況は個人ページの該当日に表示
- **日報（業務報告）**: メンバーは `/me` で当日の業務内容を記録でき、管理者は
  「日報」タブで日付ごとに全員分を確認（未提出者も分かります）。個人ページの
  タイムラインには日報のある日に 📝 が付き、クリックで内容を表示できます
- **設定**: 会社名／サービス名（ヘッダー表示）・タイムゾーン・勤務時間帯の目安・
  作業区分・撮影間隔（頻度）・画質・ぼかし・全社撮影 ON/OFF・キャプチャ保存日数・
  連続在席アラート閾値を画面から変更。撮影設定はクライアントの次の撮影
  サイクルから自動反映されます
- **勤務時間帯の帯**: 設定した勤務時間帯（既定 9:00〜18:00）がタイムライン上に
  薄い帯で表示され、在席が時間内/時間外かひと目で分かります
- **予定勤務時間・残業/不足**: 1日の予定勤務時間（既定 8 時間）を設定でき、
  月次レポートに残業・不足を集計、個人ページの各日に過不足を表示します
- **通知（Slack / メール）**: 着席・退席や長時間在席アラートを Slack の Incoming
  Webhook や SMTP メールへ通知できます（設定画面で「テスト送信」可）
- **メール対応（受信箱の優先度分類・AI返信）**: 共有の受信箱（例: info@…）を IMAP で
  定期取得し、**専用画面 `/mail`** に**受信日時の新しい順**で表示します（「並び順」で重要度順（高→中→低）にも切り替えられ、どちらもブラウザごとに覚えます）。
  受信箱は「状態：すべて」で開き、返信済み・対応不要にしたメールも一覧に残して灰色で出します
  （まだ対応していないメールだけを見たいときは「状態」で「未対応」を選ぶ。選んだ状態は覚えず、開き直すと「すべて」に戻る。
  一覧に出すのは500通までで、返信済み・対応不要は新しい方だけを出すが、未対応・確認待ちのメールは古くても必ず出す）。
  一覧は重要度で色分けし（高=赤・中=だいだい・低=灰色。まだ対応していない[高]の行は薄い赤）、
  ふだんは「重要度」が「高・中」で、[低]（お知らせ・広告・自動通知）は出しません
  （出していない数を一覧の上に出す。「すべて」で[低]も出し、ブラウザごとに覚える。検索では[低]からも探す）。
  本文の下に続く前のやり取りの引用（「>」の行・「〜 wrote:」・「-----Original Message-----」・
  Outlook の「差出人: / 送信日時: / 宛先: / 件名:」から下）は畳み、「引用を表示 ▼」で開きます
  （転送のメール・HPフォームから届いたメール・途中に挟んだ短い引用は畳まない）。
  Claude API キーを設定すると優先度判定と**返信文の下書き生成**を AI が行い
  （未設定でもキーワード分類＋定型文で動作）、内容を編集して画面から
  **そのまま返信を送信**できます（送信は SMTP 設定を使用、スレッドが繋がる
  ヘッダ付き）。優先度[高]の受信は Slack/メールに通知でき、
  送信操作は監査ログに記録されます。
  AI のモデルは「返信文の作成」（既定: 高品質）と「優先度の判定」（全メールに使うので
  既定: 低価格）で別々に選べ、設定画面の「AI接続テスト」で使えるか確かめられます。
  AI を使えないとき（キーの間違い・残高不足など）は、返信文の作成・優先度の判定の
  どちらで使えていないかと理由を画面に表示します
  （キーの作り方は [DEPLOY.md](DEPLOY.md) の「メールの AI（Claude）を使えるようにする」）。
  よく使う返信文は**定型文**として設定画面に登録でき、返信画面の「定型文を入れる」で
  本文に入れられます（`{相手の名前}` `{件名}` `{日付}` はそのメールの内容に置き換わる。
  最初に3つ入っています。返信文の入れたい場所をタップしてから選ぶとその位置に入り、
  場所をタップせずに選ぶと、書きかけの返信文と置き換えてよいかを聞きます）。
  返信画面では**全員に返信**もできます（「CCの人にも送る」にチェックを付けると
  元メールの To・CC の人が CC 欄に入る。自分たち・社内の人・フォームの送信元・返信する相手は
  入らない。BCC も追加可。宛先・CC・BCC は合わせて20件まで）。設定「複数の人に届いたメールは、
  最初から全員に返信にする」（返信の送信（SMTP）のカード。最初はオン）がオンなら、ほかの人にも
  届いていたメールは最初からチェックが入り CC が入る（外すと CC は空になり、付け直すと戻る）。
  一斉送信のメール（List-Id・List-Unsubscribe のあるメーリングリスト・メルマガと、宛先・CC が
  11人以上のメール）は、オンでも最初はチェックを付けず「一斉送信のメールのため、全員に返信はオフに
  しています」と出す。メール担当者が確認をお願いした下書きは、そのときの CC・BCC をそのまま出す
  （管理者にも同じに見える）。返信画面を閉じると、書きかけの返信文と一緒に CC・BCC も残し、開き直すと
  そのまま出す（外した人を入れ直さない）。送る前の確認には、宛先・CC・BCC を全部出す（宛先と同じ人は
  CC・BCC から除いて出す。実際にも2通は送らない）。
  宛先・CC・BCC の欄に名前やアドレスの一部を打つと、**候補**が欄のすぐ下に出ます
  （設定画面の「**よく使うアドレス**」（アドレス帳）に入れた人が先、次に前にやり取りした人
  ― 届いたメールの相手と、こちらが返信を送った宛先・CC・BCC ― を、やり取りの多い人・
  最近の人から8人まで。名前・アドレス・メモ・取引先の名前で探す。自分たちのアドレスと
  フォーム・自動送信の送信元は出さない。タップか Enter で「名前 <アドレス>」が入り、CC・BCC は
  続けて次の人を打てる。PC は ↑↓ で選び Esc で閉じる）。アドレス帳は管理者が設定画面で
  追加・変更・削除でき、返信画面の「この相手をアドレス帳に追加」でも入れられる
  （メール担当者は候補を使うだけ）。
  届いたメールの**添付ファイル**も返信画面で見られます（一覧で 📎 が付く。
  写真は縮小表示、ほかは「ダウンロード」。1つ15MB・1通で合わせて40MBまで保存し、
  それより大きいものは「大きすぎるため保存していません」と名前だけ出る。
  サーバの空きが少ないとき・保存している添付が合わせて10GBに達したときも保存しない。
  この機能を入れた後に届いたメールから保存）。
  届いたメールは**問い合わせの種類**（清掃のご依頼・予約・宿泊のお問い合わせ・
  請求・お支払い・運営代行のご相談・営業・宣伝・その他）に自動で仕分け、
  種類ごとの**担当**も自動で入ります（AI を使うときは優先度と同じ1回の依頼で種類も選び、
  使わないときは設定の言葉で決める。受信箱の**タブ**（すべて・重要（高）・種類ごと・未分類。数字は未対応と確認待ちの数（「状態」で未対応か確認待ちを選んでいるときはその数）で、1分ごとに新しくなる）で分けて見られ、「担当」で絞り込め、返信画面で変えられる。
  種類の一覧・言葉・担当は設定画面の「種類と担当」で変えられる）。
  新しいメールは**自動で受信**し（既定 5 分ごと。設定画面の「自動受信の間隔」で 1〜60 分。
  サーバを起動・更新したときは 30 秒ほどで1回目を受信）、**開いたままの受信箱も 1 分ごとに
  新しくなります**（ページの再読み込みは不要。タブの名前に未対応の数、前に見た後に届いて
  まだ開いていないメールに「新着」、「今すぐ受信」の横に最終受信の時刻、受信に失敗していれば
  その理由を出す。返信画面・設定を開いている間は描き直さず、戻ったときに新しくする。
  自動の受信と「今すぐ受信」は重ならないよう1つずつ行う）。
  返信画面のメール本文は、長くても最初から全部出ます（「全文を表示」を押さずに、返信画面ごと下へ
  進んで読める。長い URL なども折り返して、横にはみ出さない）。
  返信画面には**この相手とのやり取り**が出ます（同じアドレスから届いたほかのメールと、
  返事のヘッダ（Message-ID・In-Reply-To・References）でつながるメール ― 別のアドレスからの
  同じ話の返事など ― を、こちらが送った返信と一緒に新しい順に30件まで。押すと開き、
  1通ずつ全文を見たり、そのメールを開いたりできる。受信箱では差出人の横に
  「やり取り N件」（同じ相手から届いたほかのメールの数）が出る）。
  受信箱の行の右の「**本文 ▼**」を押すと、返信画面を開かずに、その行のすぐ下に本文と
  **この後のやり取り**（こちらが送った返信 ―「↩ こちらの返信」と送った時刻・送った人 ― と、
  後から届いた同じ相手・同じ話のメール）が時刻順に出ます（プルダウン。もう一度押すか「閉じる」で
  たたむ。いくつ開いてもよく、自動で新しくなったとき・タブを切り替えたときも開いたまま。
  「前のやり取りも見る」で前のメールと返信も出せる。中の「返信画面を開く」で返信画面、
  管理者は未対応のメールなら「対応不要」も押せる。件名など行のほかの所を押すと今までどおり
  返信画面が開く。ほかのメール・返信の本文は1通2万文字まで、この後・前それぞれ30通まで）。
  **HPのお問い合わせフォーム**（WordPress の Contact Form 7 など）から届くメールは、差出人が
  どのお客様の分も同じ（wordpress@… など）なので、Reply-To か本文の「メールアドレス: …」の
  お客様を相手にします（受信箱にはお客様の名前と「HPフォーム経由」が出て、別々のお客様が
  同じやり取りにまとまらない。返信もお客様のアドレスに送り、返信画面の宛先の欄で確かめて
  直せる。本文にアドレスが無いときは、宛先を入れてもらう）。wordpress@・noreply@ などは
  自動で分かり、分からないフォームは設定画面の「メールの受信」の
  「HPのお問い合わせフォームの送信元」に書く。前の版で返信がフォームの送信元に送られていた
  メールには、返信画面と設定画面に注意が出る）。
  上の「**取引先**」を押すと、取引先（会社・お客様）ごとに、前に届いたメールとこちらが送った返信を
  新しい順にまとめて見られます（はじめと最後のやり取りの日・数・種類ごとの数・未対応の数も出る。
  探す欄で名前・アドレス・ドメインから探せる）。会社のアドレスは @ の後ろ（ドメイン）ごとに1つ、
  Gmail・携帯のメールや Airbnb などの予約サイトのアドレスは1人ずつ（この一覧は設定画面の
  「取引先の分け方」で変えられる）。自分たちのアドレスとフォーム・自動送信の送信元は入れない。
  管理者は取引先の画面で、名前・メモを付けたり、ほかのアドレス・ドメインをまとめたり、
  会社の中の1人を別の取引先に分けたりできる（変えてもメールは変わらない。操作の記録に残る）。
  メール担当者は見るだけ。返信画面にも取引先の名前と「この取引先のやり取りをすべて見る」が出る。
  届いてから決めた時間（既定: 優先度[高]は2時間・[中]と[低]は24時間）がたっても「未対応」の
  ままのメールは、**Slack・メールでまとめてお知らせ**します（1通につき1回。夜21時〜朝8時は
  止めておき、終わった後にまとめて送る。送り先・時間・時間帯は設定画面の
  「返事をしていないメールのお知らせ」で変えられ、「テスト送信」で確かめられる。
  送り先が無ければ何も送らない。この機能を入れる前に取り込んだメールは直近7日の分だけ）。
  **週ごとのまとめ**も同じ送り先へ送れます（設定画面の「週ごとのまとめ」でオンにすると、
  毎週決めた曜日・時刻（既定: 月曜9時・日本時間）に、その前の7日間に届いたメールの数
  （優先度・種類ごと）、返信した数と返信までの時間、対応不要にした数、いま未対応のメール、
  よく届いた差出人（アドレスは縮める）などを1通で送る。既定はオフ。「見本を見る」で文面を、
  「今すぐ送る」で届くかを確かめられる）。
  返信画面の**カレンダーに登録**で、メールに書かれた日付（清掃日・内見日など）を予定にできます
  （AI を使うときは AI が、使わないときは「2026/10/25」「10月25日(土)」「10/25 14:00」「14時〜16時」
  「午後2時」「明日」「来週の火曜日」などの書き方から探す。年が無い日付は届いた日から見て次に来る日。
  名前・日時・場所・メモは画面で直せ、「Googleカレンダーで開く」で内容の入った Google カレンダーの
  登録画面を新しいタブで開くか、「予定ファイル(.ics)を保存」で iPhone のカレンダー・Outlook などに入れる。
  サーバに Google のログインは不要で、サーバから Google へは何も送らない）。
  返信画面の**Notionに登録**で、問い合わせのメールを Notion のデータベース（運営代行 案件DB など）に
  1件＝1行で登録できます（列には「列に入れるもの」の設定と、AI を使うときは AI がメールから読み取った
  案件名・所在地などを、列の種類と選択肢に合うものだけ入れる。ページの中に差出人・受信日時・本文、
  添付ファイルは Notion にアップロードして並べる。登録したら「Notionで開く」になり二重には登録しない。
  設定は画面の「Notion（案件DB）」。手順は [DEPLOY.md](DEPLOY.md) の「問い合わせを Notion の案件DBに
  登録できるようにする」）。
  **複数のメールアドレス**（例: kurosu@… と info@…）をまとめて1つの受信箱で受信できます
  （設定画面の「受信するメールアドレス」で追加・変更・止める・削除。アドレスごとに「接続テスト」。
  2つ以上あると受信箱の件名の前に「宛先: 黒須」のように届いたアドレスが出て、「アドレス」で絞り込める。
  返信は届いたアドレスを差出人にして送り、控えもそのアドレスの送信済みフォルダに残す。
  送信のログインはアドレスごとに入れなければ共通の SMTP 設定。1つのアドレスの受信に失敗しても
  ほかのアドレスは受信し、受信箱の注意書きにどのアドレスかを出す。アドレスを削除しても届いたメールは
  残り「削除したアドレス」と出る。それまでの受信サーバの設定は、更新後の最初の起動で1つ目の
  アドレスになり、続きから受信する）。
  上の「**送信箱**」で、こちらから送ったメールを新しい順に見られます（この画面から送った返信と、
  各アドレスの送信済みフォルダから自動で取り込んだもの ― お名前メールの Webメール・Outlook・スマホ・
  Gmail などから送ったメール ― を一緒に出す。行を押すと本文の全文・宛先・CC（BCC はこの画面から
  送ったものだけ）・添付・元のメール・取引先。管理者とメール担当者が見られる）。
  送信済みフォルダは読むだけで（メールボックスは変えない）、受信と同じ回に差分だけ読み、初めては
  「初回に遡る日数」の分だけ。この画面から送った返信の控えは Message-ID で見分けて二重に出さない。
  Webメールなどから**届いたメールに返信すると、受信箱のそのメールも自動で「返信済み」**になる
  （In-Reply-To・References でつながるもの。つながりが無いときは、宛先が相手で件名（Re: などを除く）が
  同じ未対応のメールが1通だけ・送った時刻より前に届いていて、件名が「Re:」などで始まるときだけ（「ご連絡」の
  ような件名で新しく書いたメールでは、元のメールにつなぐだけ）。宛先か CC に相手が入っているときだけで、
  転送（Fw:）や、外注先・社内の人など相手でない人・自分たちだけへのメールでは変えない。HPのフォームから届いた
  メールは、本文などから決めたお客様に送ったときだけ（Webメールの「返信」で webmaster@・noreply@ などの
  フォームの送信元に送ったものでは変えない。お客様が分からないフォームのメールも変えない）。直接の返信の元
  （In-Reply-To。無ければ References の最後）のメールをまだ取り込んでいないときは、そのメールが届いてから
  そちらを返信済みにする。後から届いたメールを返信済みにするのは、そのメールへの直接の返信で、届いた後に
  相手へ送ったものだけ（そのときも優先度[高]の知らせは出す）。返信済み・対応不要のメールは変えない。
  確認待ちのメールは返信済みにする（あとで「承認して送信」を押してお客様に2通目を送らないように。担当者の
  下書きは送らず、返信画面にそう出す）。この画面から送って宛先に届かなかった返信（CC・BCC の人にだけ
  届いたもの）の控えでは変えない（前の版が残した控えも、操作の記録の宛先・件名・時刻で見分ける。前の版の控えで
  返信済みにしてしまっていたメールは、起動したときに未対応に戻す）。操作の記録の操作者は「（自動）」）。
  返信画面には「Webメールなどから返信してあります」と送った文が出る。Gmail は、アドレスの
  「**送信済みだけ取り込む（受信箱には入れない）**」でつなぐと、受信箱には入れずに送ったメールだけを取り込む
  （IMAP を有効にし、2段階認証の「アプリ パスワード」で imap.gmail.com:993。送信済みフォルダは自動で探す）。
  **送信箱はメール担当者みんなが見られる**ので、このアドレスからは仕事のメールだけを取り込む（受信箱のメールへの
  返信と、アドレス帳の人・前にメールをくれた相手に送ったもの。前にメールをくれた相手は、対応不要にしただけの人は
  数えず、Gmail などの誰でも作れるアドレスの人は返信したことがある人だけ。家族・友人などへの私用のメールと、
  その添付は入れない）。
  アドレスごとに「送信済みも取り込む」を外すこともできる。
  受信箱と送信箱の上の**検索欄**で、件名・本文・相手（差出人・宛先・CC の名前とアドレス）・
  名前を付けた取引先の名前・添付ファイルの名前から探せます（日本語の言葉の途中・1文字でも見つかる。
  空白で区切ると全部を含むメールだけ。全角の英数字で打っても見つかる。探した言葉に色が付き、
  件名の下に本文の言葉のあたりが出る）。タブ・担当・アドレスの絞り込みと一緒に効き、探している間は
  「状態」が「すべて」になって返信済み・対応不要からも探す（選び直せばその状態の中だけ。やめると元の状態）。
  1分ごとの自動更新でも言葉はそのまま。何万通でも速いよう、SQLite の FTS5（trigram）の索引を
  DB のトリガーでいつも合わせる（前からあるメールは起動後に少しずつ入れる。入れ終わるまでと、
  FTS5 が使えない SQLite では、新しい方から2万通を1通ずつ見て探す）。
  **スタッフ（メール担当者）に下書きを任せる**こともできます（設定画面の「メール担当者」で、
  登録されている人を「担当にする」。その人は自分のトークンでメール画面に入り、受信箱を見て
  返信文を作れる（生成・定型文・CC・BCC・種類と担当も使える）が、**送信はできない**。
  「確認をお願いする」を押すと「確認待ち」になり、Slack・通知先メールに知らせが届く。
  管理者は受信箱の「確認待ち」から開き、返信文を確かめて（直してもよい）「承認して送信」するか、
  コメントを書いて「差し戻す」（未対応に戻り、メール担当者の返信画面にコメントが出る）。
  設定・定型文の管理・Notion・対応不要にするは管理者だけ。どれもサーバ側でも止める。
  返事のいらないメールは、受信箱の行の右の「**対応不要**」（管理者だけ。未対応の行に出る）か、
  返信画面のいちばん上（件名の上、「閉じる」の隣）の「対応不要にする」を1回押すだけで対応不要になります
  （対応不要は「返信しなくてよい」印で、メールは受信箱に残り、灰色で「対応不要」と出る。
  「状態」で「未対応」を選んでいるときだけ一覧から外れる。確かめの画面は出さない。
  間違えたときは、画面の下に6秒ほど出る「元に戻す」で未対応に戻せる。続けて何通も対応不要にしたときは、
  古い知らせを「（3通）」のようにまとめて「3通とも元に戻す」にし、返信画面を開いている間は知らせを消さない。
  行が消えて下の行が上がった・行の「対応不要」が消えて「本文 ▼」などがその場所に来た直後は、同じ所をもう一度押しても何もしない
  （次のメールを対応不要にしたり、対応不要にしたばかりのメールのプルダウン・返信画面を開いたりしない。
  対応不要にしたメールは見たことにして「新着」の印も外す）。押している間にほかの人が
  返信した・確認をお願いしたメールは対応不要にせず、理由を出す。どちらも操作の記録に残る）。
  人の追加とトークンは勤怠の管理画面か `python manage.py add-user 名前 --mail-staff`）。
  勤怠管理とは**別のUI**ですが、同じサーバ・同じDB・同じ管理者トークンで、
  **同じドメインの `/mail`** で開きます（例 `kintai.example.com/mail`）。
  メールだけ別ドメインにすることもできます（[DEPLOY.md](DEPLOY.md) 参照）
- **連続在席アラート**: 閾値（既定 6 時間）を超えて着席し続けているメンバーに
  稼働状況で ⚠ を表示し、設定により Slack/メール通知も送ります
- メンバー管理から**個人ごとの撮影停止/再開**も可能（本家 F-Chair+ と同様、
  会社全体・ユーザー個人の両方で頻度変更・停止ができる設計）

日付・月の集計境界は管理画面の**タイムゾーン設定**（既定 `Asia/Tokyo`、環境変数
`ZATSUMU_TZ` で初期値を指定）で判定します。

**月次レポート / CSV 出力**:

```bash
# JSON
curl "http://<server>:8000/api/reports/monthly?month=2026-05" -H "Authorization: Bearer <管理者トークン>"
# CSV ダウンロード（Excel 対応の BOM 付き）
curl "http://<server>:8000/api/reports/monthly.csv?month=2026-05" -H "Authorization: Bearer <管理者トークン>" -o report.csv
```

`month` を省略すると当月を集計します。

**スクリーンショットの保存期間（自動削除）**:

- サーバ起動中、`ZATSUMU_RETENTION_DAYS`（既定 30 日）より古いスクショを
  `ZATSUMU_PURGE_INTERVAL_HOURS`（既定 6 時間）ごとに自動削除します（0 で無効化）。
- 手動実行: `python manage.py purge --days 30`、または `POST /api/admin/purge`（管理者）。

### 新しい端末のメール確認（任意）

サーバの `.env` に `ZATSUMU_LOGIN_VERIFY_EMAIL=you@example.com` を書くと、管理者が
初めて使う端末（パソコン・スマホ）からログインしたとき、そのアドレスに 6 桁の確認コードを
メールで送り、入力するまで使えなくなります（2段階認証）。空なら無効で、今までどおりです。
メンバーの打刻は対象外です。メール担当者（スタッフ）も、メール画面を初めて使う端末では
確認コードが要ります（コードは同じアドレスに届くので、本人からのログインか確かめてから伝える。
打刻は今までどおり確認なし）。

- 確認できた端末には「端末トークン」（端末用の合言葉）を渡し、画面はそれを
  `X-Device-Token` ヘッダで毎回送ります。90 日使わなければ失効します。
- 端末トークンが無い管理者のリクエストは `401` `{"detail": "device_verification_required"}`
  になります（画面はこれを見て確認コードの入力画面を出します）。
- メールが届かないときの復旧は `python manage.py issue-device <管理者の名前>`。
  一覧・取り消しは `devices` / `device-revoke <番号|all>`。詳しくは [DEPLOY.md](DEPLOY.md)。
- メール専用サーバでは、更新のあと `docker compose up -d --force-recreate caddy` で
  Caddy（入口の門番）を作り直してから有効にしてください。作り直さないと確認用の道
  （`/api/device`）が 404 のままで、確認コードの画面から先へ進めません。
