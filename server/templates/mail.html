取引先

使い方を見る

メールの相手を、取引先（会社・お客様）ごとにまとめています。行を押すと、その取引先から届いた メールと、こちらが送った返信を、新しい順にまとめて見られます。 会社のアドレス（例: tanaka@abc.co.jp と suzuki@abc.co.jp）は、@ の後ろ（abc.co.jp）が同じなら 1つの取引先になります。Gmail・携帯のメールや、Airbnb などの予約サイトから届くメールは、1人ずつ別の取引先です。 HPのお問い合わせフォームから届いたメールは、本文に書かれたお客様の取引先に入ります。 自分たちのアドレスと、フォーム・自動送信の送信元（wordpress@・noreply@ など）は取引先になりません。 名前を付けたり、まとめ方を直したりするのは、取引先を開いた画面でできます（管理者だけ）。

使い方を見る

この取引先から届いたメール（📩）と、こちらが送った返信（↩）を、新しい順に並べています。 行を押すと全文が出て、「このメールを開く」で返信画面を開けます（返信画面を閉じると、この画面に戻ります）。 上の数は、この取引先のメール全部の数です（未対応は、まだ返信も「対応不要」もしていないメール）。 管理者は、下の「取引先の設定」で名前・メモと、まとめるアドレス・ドメインを変えられます （変えてもメールは変わりません。取引先を消すと、元の分け方に戻ります）。

やり取り

設定

確認済みの端末（新しい端末のメール確認）

メールの確認コードで確認した端末の一覧です。心当たりの無い端末や、 なくした端末は「取り消し」を押してください（その端末では次の操作から 確認コードが必要になります）。

受信するメールアドレス

ここに入れたメールアドレス（例: kurosu@… と info@…）に届いたメールを、 まとめて1つの「受信箱」に出します。返信は、メールが届いたアドレスを差出人にして送ります。

アドレスを追加

Gmail など、そのアドレスに届いたメールは受信箱に入れず、そこから送ったメールだけを 「送信箱」に出したいときにチェックします（届いたメールへの返信なら、受信箱のメールも自動で「返信済み」になります）。 このアドレスから届いたメールは、自分たちが送ったものとして受信箱に入れません。

⚠ 取り込んだメールは、メール担当者みんなが送信箱で見られます（本文・添付も）。 私用のメールを見られないよう、取り込むのは仕事のメールだけです: 受信箱のメールへの返信と、前にメールをくれた相手・ アドレス帳の人に送ったもの。それ以外（家族・友人・お店などへのメール）は取り込みません。

Gmail をつなぐには
  1. Gmail の「設定」→「すべての設定を表示」→「メール転送と POP/IMAP」で「IMAP を有効にする」を選んで保存します。
  2. Google アカウントの「セキュリティ」で「2段階認証プロセス」をオンにし、「アプリ パスワード」を作ります（16文字の英字。ふだんのパスワードではログインできません）。
  3. ここで「メールアドレス」と「IMAPユーザー」に Gmail のアドレス、「IMAPサーバ」に imap.gmail.com、「IMAPポート」に 993、「SSLで接続」をオン、「IMAPパスワード」にアプリ パスワードを入れ、「送信済みだけ取り込む」にチェックして追加します。
  4. 送信済みのフォルダ（[Gmail]/送信済みメール や [Gmail]/Sent Mail）は自動で見つけます。追加したら「接続テスト」で確かめてください。

パスワードはこの欄にだけ入れてください（チャットやメールで人に送らないでください）。 画面には出ず、変えるときだけ入れ直します。

くわしい設定（ふつうはそのままで大丈夫です）

送信用のユーザーとパスワードは、ふだんは空のままで大丈夫です （下の「返信の送信（SMTP）」の共通の設定で送ります）。返信を送ったときに 「差出人のアドレスを断られました」と出るアドレスだけ、そのアドレスで送信サーバに ログインするユーザー（ふつうはメールアドレス）とパスワードを入れてください。

IMAPサーバ・ユーザー・パスワードは、メール業者（レンタルサーバ）の案内に書いてあります （同じ会社のアドレスなら、サーバはふつう同じです）。名前は受信箱の「宛先」に出ます（空なら アドレスの @ の前）。「株式会社◯◯ <info@…>」のように入れると、返信の差出人に名前も出ます。 受信箱のメールは変更しません（既読も付きません）。この画面から送った返信は、そのアドレスの 送信済みフォルダにも控えを残すので、Webメールの「送信済み」からも見られます。 「止める」と、そのアドレスは受信しません（届いたメールは残ります）。「削除」しても、 届いたメールは消えません（受信箱では「削除したアドレス」と出ます）。 パスワードは画面に出ません（変えるときだけ入れてください）。 このカードは、ボタンを押したときに保存されます（下の「保存」は要りません）。 追加・変更したら「接続テスト」で確かめてください。

メールの受信

新しいメールが届いていないか、何分ごとに受信サーバへ確かめに行くかです （1〜60分。おすすめは5分）。短くすると早く届きますが、受信サーバへの接続が増えます。 開いている受信箱の画面は、押さなくても1分ごとに自動で新しくなります （ブラウザのタブの名前に、未対応の数が出ます）。

★フラグを付けたメールは、日数を過ぎても消しません（★を外すと、次の片付けで消えます）。

「受信するメールアドレス」のメールボックスを定期的に受信し、「受信箱」に優先度順で 表示します。初めて受信するアドレスは「初回に遡る日数」の分だけ前のメールから取り込みます。 添付ファイルもこのサーバに保存し、「メール保存日数」を過ぎるとメールと一緒に消えます。

HPのお問い合わせフォームから届くメールは、どのお客様の分も 差出人が同じアドレス（wordpress@… など）になります。このアドレスから届いたメールは、本文の 「メールアドレス」の欄に書かれたお客様を相手にします（受信箱にはお客様の名前と「HPフォーム経由」が出て、 返信もお客様に届きます）。wordpress@・noreply@ のような送信元は、ここに書かなくても分かります。 それでも差出人のまま出てしまうフォームがあれば、その差出人のアドレスを書いてください （「@example.co.jp」と書くと、そのドメインから届いたメール全部）。保存すると、届いていたメールも直します。

取引先の分け方

「取引先」の画面では、会社のアドレスは @ の後ろ（ドメイン）が同じなら1つの取引先に まとめます（tanaka@abc.co.jp と suzuki@abc.co.jp は「abc.co.jp」）。下の一覧のドメインは、会社ではなく 1人ずつ別の取引先にします（Gmail・携帯のメール・プロバイダのメールと、Airbnb などの予約サイトの 中継のアドレス）。「airbnb.com」と書くと、guest.airbnb.com のようなその下のドメインも入ります。

変えた内容は下の「保存」で保存され、すぐ取引先の画面に使われます （メールは変わりません）。会社ごとに名前を付けたり、まとめ方を直したりするのは、取引先の画面でできます。

AI返信（Claude）

キーは Anthropic 社の管理画面 console.anthropic.com の「API Keys」で作れます。 AIを使った分だけ料金がかかります（Anthropic 社からの請求です）。 キーはパスワードと同じです。チャットやメールに貼り付けたり、人に教えたりしないでください （もれたときは管理画面でそのキーを削除し、作り直してください）。

優先度の判定は届いたメール全部に使うので、安くて速い「低価格」がおすすめです （問い合わせの種類も、このとき一緒に選びます）。 返信画面の「カレンダーに登録」でメールから日付を読み取るときも、このモデルを使います。 「受信時に下書きを自動生成」がONだと、メール1通ごとに返信文用のモデルも使います （費用を抑えたいときはOFFにして、必要なメールだけ「返信文を生成」を押してください）。

APIキーを設定すると、優先度の判定と返信文の下書きをAI（Claude）が行います。 未設定でもキーワードによる分類と定型文の下書きで動作します。 キーの間違いや残高不足などでAIを使えないときも、自動でキーワード判定・定型文に切り替わり、 理由をこのカードと受信箱に表示します。キーやモデルを変えたら「保存」→「AI接続テスト」で 確かめてください。 返信は必ず内容を確認してから送信してください。

返信の送信（SMTP）

返信の送信と通知メールに使います。この設定は勤怠管理の通知メールと共通です （どちらの画面で変更しても同じ設定が変わります）。返信の差出人は、メールが届いたアドレス （「受信するメールアドレス」）です。ここの差出人メールは、通知メールと、一覧から削除した アドレスに届いたメールへの返信に使います。

オンにすると、返信画面の「CCの人にも送る（全員に返信）」に最初からチェックが入り、元のメールの宛先・CC に入っていた人が CC に入ります（自分たち・社内の人・フォームの送信元・返信する相手は入れません）。いらない人は CC の欄から消すか、チェックを外してください。送る前の確認に、届く人を全部出します。メーリングリストなどの一斉送信のメール（宛先・CC が11人以上のものも）は、オンでも最初はチェックを入れません。メール担当者の画面も同じです。

返事をしていないメールのお知らせ

届いてからこの時間がたっても「未対応」のままのメールを、 Slack やメールでまとめてお知らせします（1通につき1回だけ。返信するか「対応不要」にすれば、お知らせしません）。 0 にすると、その優先度のメールはお知らせしません。

お知らせしない時間帯 〜

夜中などに届かないよう、この時間帯はお知らせを止めておき、 終わった後にまとめて送ります（日本時間）。「なし」にすると、いつでも送ります。

お知らせは、ここに入れた送り先に届きます（両方入れれば両方）。 通知先メールには「返信の送信（SMTP）」の設定で送ります。どちらも空なら、お知らせはしません。 この2つは「優先度[高]の受信を通知」や勤怠管理の通知と共通です。 Slack の URL は、Slack の「Incoming Webhook」で作れます（パスワードと同じように扱ってください）。

お知らせに載せる、この画面のアドレスです（押すと受信箱を開けます）。

週ごとのまとめ

毎週この曜日・時刻（日本時間）に、 その前の7日間（月曜なら、前の週の月曜〜日曜）のメールの様子を1通にまとめて送ります。 届いたメールの数（優先度・種類ごと）、返信した数と返信までの時間、対応不要にした数、 いま未対応のメール、よく届いた差出人などです。 送り先は「返事をしていないメールのお知らせ」と同じ（通知先メール・Slack）です。

    2. 
        
  2. 作った連携の「シークレット」を「表示」→「コピー」し、下の「Notionのシークレット」に
        貼り付けます。シークレットはパスワードと同じです。チャットやメールには貼り付けないで
        ください（もれたときは、同じ画面でシークレットを作り直してください）。
    3. 
        
  3. Notion で案件DBを開き、右上の「…」→「接続」から、作った連携を選んで追加します
        （これをしないと「連携が招待されていません」と出ます）。
    4. 
        
  4. 案件DBのURL（ブラウザのアドレス欄の文字。「…」→「リンクをコピー」でも取れます）を
        下の「データベースのURL」に貼り付けて「保存」を押し、「Notion接続テスト」で確かめます。
    5. 
      

      
      
      
      
      
保存すると、URLの中のデータベースの番号（ID）だけが残ります。

      
      
「AI返信（Claude）」のキーがあるときだけ使います。AI がメールを読んで、
      案件名と、所在地・間取りなどメールに書いてある列を入れます（選択の列は Notion にある選択肢だけ。
      メールに書いていないことは入れず、空のままにします）。1回あたり 1 円未満が目安です。

      
      
      
右側に書けるもの: 件名・差出人・差出人の名前・差出人のメール・電話番号・
      受信日・受信日時・本文・種類・担当。「」で囲むと、その文字をそのまま入れます
      （例: ステータス = 「問い合わせ受付」。選択の列は、Notion にある選択肢と同じ文字にしてください）。
      「」だけにすると、その列は空のままにします（AI も入れません）。
      AI を使うときは、件名・差出人・電話番号などメールの文から読む列は、AI が読み取った値を優先します
      （ホームページのフォームから届いたメールでも、お客様の名前と連絡先が入るように）。
      ここに書いていない列も、メールに書いてあれば AI が入れます。

      
      

      

      
登録した内容（メールの本文・添付ファイル）は、そのデータベースを見られる人
      （共有している提携先なども）みんなが見られます。Notion に送るのは「Notionに登録」を押したメールだけです。
      シークレット・URL・列に入れるものは、下の「保存」で保存されます。

    

    

      
定型文（よく使う返信文）

      

      
新しい定型文

      
      
      
      
差し込み：
        
        
        
      

      
      

        
        
        
      

      
返信画面の「定型文を入れる」から選ぶと、返信文に入ります。
      本文に {相手の名前}（差出人の名前）・{件名}（届いたメールの件名）・
      {日付}（今日の日付）と書いておくと、入れるときにそのメールの内容に置き換わります
      （「差し込み」のボタンで入れられます）。【 】の部分は、物件などに合わせて書き換えてください。
      定型文は、このカードのボタンを押したときに保存されます（下の「保存」は要りません）。

    

    

      
よく使うアドレス（アドレス帳）

      
ここに入れた人は、返信画面の宛先・CC・BCC の欄に名前やアドレスの
      一部を打つと、候補の一番上に出ます（タップすると「名前 <アドレス>」の形で入ります）。
      前にやり取りした人も、入れなくても候補に出ます。メモ（例：清掃の担当・平日のみ）でも探せます。

      
      

      

      
新しいアドレス

      

        
        
        
      

      

        
        
        
      

      
アドレスは1件に1つです（何人もいるときは、1人ずつ追加してください）。
      メールソフトからコピーした「山田 太郎 <taro@example.com>」の形も、そのまま入れられます。
      追加・変更・削除は、ボタンを押したときに保存されます（下の「保存」は要りません）。
      メール担当者は、候補に出るのを使えます（変えられるのは管理者だけです）。

    

    

      
メール担当者（スタッフ）

      
「メール担当者」にした人は、自分のトークン（合言葉）でこの画面に入り、
      受信箱を見て返信文を作れます（返信文の生成・定型文・CC・BCC・種類と担当も使えます）。
      送信はできません。返信文ができたら「確認をお願いする」を押すと、管理者に知らせが届き、
      受信箱の「確認待ち」に入ります。管理者は返信画面で返信文を確かめて（直してもかまいません）
      「承認して送信」を押すか、コメントを書いて「差し戻す」を押します。
      設定・定型文の管理・Notionへの登録・「対応不要にする」は、管理者だけができます。

      
      
オフにすると「確認をお願いする」のボタンが出なくなり、メール担当者は
      返信文を下書きに残すだけになります（送信は、オンでもオフでも管理者だけです）。
      確認のお願いの知らせは、「返事をしていないメールのお知らせ」と同じ送り先（通知先メール・Slack）に届きます。

      

      

      
一覧は、このサーバに登録されている人です。「担当にする」「外す」は、押したときに保存されます
      （下の「保存」は要りません。外すと、その人は次の操作からこの画面を使えなくなります）。
      人の追加とトークン（合言葉）の発行は、勤怠の管理画面の「メンバー」で行います
      （メール専用のサーバでは、サーバで python manage.py add-user 名前 --mail-staff を実行すると、
      メール担当者として作ってトークンを表示します）。トークンは本人だけに伝えてください。
      新しい端末の確認（確認コード）を使っているときは、メール担当者が初めて使う端末でも確認コードが要ります。
      コードは管理者のメールに届くので、本人からのログインか確かめてから伝えてください。
